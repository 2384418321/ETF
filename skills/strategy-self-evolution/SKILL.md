# 策略自进化协议

一套让策略「能改、但改不乱」的流程。

核心不是让机器自动调参——是**把「该不该改」变成可以逐条核对的门，并且强制留下改前的预测和改后的对账**。

自进化最大的风险不是不进化，是**每天都进化**：拿当期盈亏当反馈去拧参数，等于用几十个样本拟合噪声。这份协议把「适当调整」量化成八道闸门。

---

## 一、先登记，再进化

没有登记的策略**不许改**。登记表在 `strategy_registry.json`，每个策略声明四件事：

| 字段 | 含义 |
|---|---|
| `params` | 可以动的参数，每个带 `value` 和 `grid`（候选网格） |
| `frozen` | 冻结项，写清楚为什么不能动 |
| `forbidden_directions` | 明确禁止的改动方向（通常是自己踩过的坑） |
| `max_dd_tolerance` | 回撤容忍线，越过就触发诊断 |

`negative_list` 是全项目共用的「不许再试」清单——已经证伪的方向不许换个说法重来。

**网格的意义**：参数只能在网格里跳，不许连续微调。`band=0.021` 这种值一律拒绝，因为它是拟合出来的，不是判断出来的。

新增策略时照抄一份 block，`status` 先设 `paper`，跑满 40 个观察期再改 `live`。

## 二、每日复盘做什么

```bash
python tools/evolve_cycle.py            # 体检，产出 reflections/evolve_<日期>.md
python tools/evolve_cycle.py --detail   # 带最近 20 期明细
```

每天只做三件事：算事实、下诊断、过闸门。**默认什么都不改。**

体检报告结构固定：

1. 区间、累计、最大回撤、近 20 期均值与胜率、尾部连续同向期数
2. 与基准的超额（ETF 闸门对 50/50 买入持有）
3. 命中哪几条现象，每条现象配候选改法与判据
4. 当前可进化参数与冻结项
5. 不许再试的方向
6. 闸门参数

四条诊断信号：

| 信号 | 触发条件 | 含义 |
|---|---|---|
| `streak_loss` | 连续 ≥3 期同向为负 | 可能真失效，也可能只是基准在跌 |
| `mdd_breach` | 回撤深于登记容忍线 | 风控破了 |
| `idle_too_long` | 连续 ≥20 交易日空仓 | 规则在当前市况下失去作用 |
| `underperform` | 同区间比基准低 ≥5pp | **单独不构成改动理由** |

`underperform` 要特别小心：趋势跟随跑输买入持有是它的设计代价，不是故障。只有「回撤也同时更差」时才允许动。

## 三、八道闸门

要动参数，八条全过：

| 闸 | 条件 | 拦什么 |
|---|---|---|
| G1 冷却 | 距上次变更 ≥10 个交易日 | 手痒 |
| G2 频次 | 同一参数 60 日内 ≤2 次 | 反复横跳 |
| G3 网格内 | 新值必须在 `grid` 里 | 连续微调等于拟合 |
| G4 确有变化 | 新旧值不能相同 | 空白变更 |
| G5 非禁令 | 不触犯 `forbidden_directions` | 重走死路 |
| G6 单一变量 | 一次只改一个参数 | 赚了不知道哪条对 |
| G7 先写预测 | 变更前写 `hypothesis` 与 `wrong_if` | 事后合理化 |
| G8 观察期 | 改后 20 个交易日不许再改 | 追着噪声跑 |

```bash
python tools/evolve_cycle.py --apply "band=0.025"   # 过闸才落地
python tools/evolve_cycle.py --rollback etf_gate    # 回滚上次
```

落地时自动写进 `reflections/evolve_cycle.jsonl`：

```json
{"date":"20261121","strategy":"etf_gate","action":"apply","param":"band",
 "from":0.02,"to":0.025,
 "hypothesis":"改 band: 0.02 → 0.025，预期改善近 20 期表现",
 "wrong_if":"改后 20 个交易日内，累计跑输基线 3.0 个百分点",
 "observe_until":"20261218"}
```

**`wrong_if` 是这套协议的核心。** 改之前就写清楚什么情况算改错了。事后再判断，人一定会给自己找理由。观察期到了拿实际数字对这句话，不对话就回滚。

## 四、硬规则

1. **不许因为当期亏损改参数。** 亏损是证据之一，不是命令。要改必须指向一个连续 ≥3 期的结构性问题。
2. **不许同时改两处。** 赚了不知道是哪个对，亏了不知道该退哪条。
3. **不许改「已证伪方向」。** 换说法也不行。`negative_list` 就是为此存在的。
4. **不许为了补亏放大仓位。** 降杠杆随时可以，加杠杆永远不行。这条写进每个策略的 `forbidden_directions`。
5. **历史期不回填。** 改动从下一期起算，旧序列不动，保证可比。
6. **回测口径必须账户级。** 现金 + 股数 + 手续费 + 只在信号翻转成交。净值序列平均、每日再平衡这类口径会凭空造出 20 个百分点的差异，本项目已经踩过。

---

## 五、改完必须对账

每次落地，都要在同一份历史数据上重算改动前后，回答三个问题：

- 多少笔交易进了 / 出了？
- 期望收益变了多少？
- 是不是只改了亏损段、盈利段没动？

只报「改完更好了」不算对账，要给出位移的数字。判据写在 `FIX_BOOK` 里，每条诊断对应一条明确的验收条件。

---

## 六、什么时候该承认「不是参数问题」

以下情况改参数是错的，应该改框架或承认证伪：

- 五年里只有一两年有效 → 窗口拟合，不是策略
- 加任何过滤器都改善不了 → 边际本身是噪声
- 收益高度集中在单一区间 → 靠的是一次运气
- 换任何参数都跑不赢最朴素的基准 → 选股层没有 α

本项目已据此把「追涨停」「龙虎榜」「行业动量」「44 因子」「Minervini」五类方向钉进 `negative_list`，不再回头。

## 七、文件与命令

| 文件 | 作用 |
|---|---|
| `strategy_registry.json` | 策略登记表，唯一权威配置 |
| `tools/evolve_cycle.py` | 体检 + 闸门 + 落地 + 回滚 |
| `reflections/evolve_<日期>.md` | 每日体检报告 |
| `reflections/evolve_cycle.jsonl` | 变更账（机器读） |
| `reflections/skill-changelog.md` | 变更账（人读，含影响面与回归验证） |

骨架：

```
每日收盘 → evolve_cycle.py 体检 → 有诊断? ──否──→ 记录，结束
                                    │是
                                    ↓
                          有候选改法且八闸全过? ──否──→ 记入待决，等下一轮
                                    │是
                                    ↓
                          写下 hypothesis / wrong_if
                                    ↓
                              apply → 影响面对账
                                    ↓
                     观察 20 个交易日 → 对账 wrong_if
                                    │
                          ┌─────────┴─────────┐
                       没改错               改错了
                          ↓                   ↓
                     转正，进 changelog    rollback，记原因
```

**自进化不等于自优化。** 这套东西能做的是：让每次改动都有据、可查、可退。它不能把噪声变成信号。

---

## 八、改动必须离开这台机器

策略和技能不是只活在本地的。**任何策略或技能的改动，都要立刻同步到 GitHub 仓库 `2384418321/ETF`。**

```bash
python tools/publish_etf.py            # 同步 + 脱敏扫描 + 冒烟 + 提交 + 推送
python tools/publish_etf.py --check    # 只看有没有漂移，不动文件
```

分工是一条硬边界，别混：

| 东西 | 唯一实现在哪 | 同步方向 |
|---|---|---|
| 信号逻辑、回测代码 | `publish/ETF/`（仓库） | 线上 `tools/etf_gate.py` **import** 它，不复制逻辑 |
| `strategy_registry.json` | 线上项目根 | 裁出 `etf_gate` + 清空台账字段 → 仓库 |
| `tools/evolve_cycle.py` | 线上 `tools/` | 整份镜像 → 仓库 |
| `skills/strategy-self-evolution/SKILL.md` | 线上 `skills/` | 整份镜像 → 仓库 |
| 台账 xlsx | 线上项目根 | **永不入库** |

`--apply` 与 `--rollback` 落地成功后会自动调一次 `tools/publish_etf.py`，所以改参数这个动作本身就把仓库更新掉了；每日 21:30 复盘再跑一次作兜底。同步失败不会撤销已经过闸的改动，但会把失败原因打出来——不许手动 `git push` 绕过扫描和冒烟。

扫描拦的是本机信息外泄：用户名、盘符绝对路径、台账文件名、token 形状、计算机名。冒烟拦的是**推上去的东西跑不起来**：出信号、复现回测基准（总 +29.8%）、体检启动，三项全过才推。

换台电脑能不能直接接手，判据只有一条：**`git clone` 之后，不靠任何人讲，照着 `docs/TAKEOVER.md` 能跑出当天信号。** 你自己试一遍，比读十遍文档确定。
